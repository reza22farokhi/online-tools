JSON چیست؟ راهنمای جامع و ساده برای مبتدیان

📅 ۱۹ آذر ۱۴۰۵ ⏱️ ۷ دقیقه مطالعه

اگر در حوزه برنامه‌نویسی، توسعه وب، یا حتی کار با APIهای مختلف فعالیت می‌کنید، حتماً نام JSON به گوشتان خورده است. اما JSON واقعاً چیست و چرا این‌قدر مهم شده است؟

JSON چیست؟

اگر با فایل‌های JSON کار می‌کنید و با خطاهای آن مواجه شده‌اید، پیشنهاد می‌کنیم راهنمای فرمت‌بندی و رفع خطاهای JSON ما را مطالعه کنید.

JSON (مخفف JavaScript Object Notation) یک فرمت سبک برای تبادل داده است که برای خوانایی انسان و پردازش ماشین طراحی شده. در واقع، JSON یک زبان برنامه‌نویسی نیست، بلکه روشی برای ذخیره و انتقال اطلاعات است.

JSON توسط Douglas Crockford در اوایل دهه ۲۰۰۰ معرفی شد و اکنون استاندارد جهانی تبادل داده در وب است. اکثر APIهای مدرن (توییتر، گوگل، تلگرام، و...) داده‌ها را در قالب JSON برمی‌گردانند.

ساختار JSON چگونه است؟

JSON از دو ساختار اصلی تشکیل شده:

۱. آبجکت (Object)

مجموعه‌ای از جفت‌های «کلید: مقدار» که بین آکولاد `` قرار می‌گیرند. 

{
  "name": "Ali",
  "age": 30,
  "city": "Tehran"
}

۲. آرایه (Array)

لیستی از مقادیر که بین کروشه `[]` قرار می‌گیرند. 

["Ali", "Sara", "Reza"]

قوانین مهم JSON

  • همه کلیدها باید در کوتیشن دوگانه باشند
  • مقادیر رشته‌ای نیز در کوتیشن دوگانه هستند
  • اعداد بدون کوتیشن هستند
  • کاما بعد از آخرین آیتم مجاز نیست
  • کامنت‌گذاری مجاز نیست
  • استفاده از تک‌کوتیشن مجاز نیست

چرا JSON محبوب است؟

  1. خوانایی بالا: انسان می‌تواند JSON را راحت‌تر از XML بخواند
  2. پردازش سریع: مرورگرها JSON را بسیار سریع‌تر از XML پارس می‌کنند
  3. پشتیبانی جهانی: همه زبان‌های برنامه‌نویسی از JSON پشتیبانی می‌کنند
  4. حجم کم: JSON حجم کمتری از XML دارد

مقایسه JSON و XML

در JSON: 

{"name": "Ali", "age": 30}

همان داده در XML: 

<person>
  <name>Ali</name>
  <age>30</age>
</person>

همان‌طور که می‌بینید، JSON بسیار مختصرتر است.

کاربردهای JSON

  • APIها: اکثر APIهای وب از JSON استفاده می‌کنند
  • فایل‌های تنظیمات: package.json در Node.js
  • ذخیره‌سازی موقت: localStorage مرورگر
  • تبادل داده بین سیستم‌ها: استاندارد صنعتی
  • پایگاه داده NoSQL: MongoDB از فرمت BSON (مشابه JSON) استفاده می‌کند

ابزارهای JSON در سایت ما

اگر با JSON کار می‌کنید، این ابزارها می‌توانند به شما کمک کنند:

  • فرمت‌کننده JSON - مرتب‌سازی، فشرده‌سازی و اعتبارسنجی
  • رمزگذار Base64 - برای انتقال امن JSON حاوی کاراکترهای خاص
  • مبدل CSV به JSON - برای کار با داده‌های جدولی

اشتباهات رایج در کار با JSON

  1. استفاده از تک‌کوتیشن: {'name': 'Ali'} نامعتبر است
  2. کامای اضافه: {"a": 1,} نامعتبر است
  3. کامنت‌گذاری: {"a": 1 /* comment */} نامعتبر است
  4. عدم escape کردن کاراکترهای خاص: باید از `\n`, `\t`, `\"` استفاده کنید

جمع‌بندی

JSON یک فرمت سبک و خوانا برای تبادل داده است که امروزه استاندارد جهانی شده. اگر با APIها، برنامه‌نویسی وب، یا هر سیستمی که داده مبادله می‌کند کار می‌کنید، یادگیری JSON ضروری است. برای کار با JSON، از ابزار فرمت‌کننده JSON ما استفاده کنید که کاملاً محلی اجرا می‌شود.

If you work in software development, web development, or with APIs, you have probably encountered JSON. But what exactly is JSON, and why has it become so important?

What is JSON?

If you already work with JSON files and need help formatting or troubleshooting them, see our guide to JSON formatting and validation.

JSON (JavaScript Object Notation) is a lightweight data-interchange format designed to be easy for people to read and straightforward for machines to parse. It is not a programming language; it is a structured way to store and exchange information.

JSON became widely adopted in the early 2000s and is now a common format for web APIs, configuration files, and communication between applications.

How is JSON structured?

JSON is built around two primary structures:

1. Objects

An object is a collection of key-value pairs enclosed in curly braces ({}). Keys must be strings enclosed in double quotes.

{
  "name": "Ali",
  "age": 30,
  "city": "Tehran"
}

2. Arrays

An array is an ordered list of values enclosed in square brackets ([]).

["Ali", "Sara", "Reza"]

Important JSON syntax rules

  • Object keys must use double quotation marks.
  • String values must also use double quotation marks.
  • Numbers are written without quotation marks.
  • A trailing comma after the final item is not allowed.
  • Comments are not part of the JSON standard.
  • Single-quoted strings are invalid JSON.

Why is JSON so widely used?

  1. Readable: Its structure is relatively easy to inspect and understand.
  2. Easy to process: Browsers and programming languages provide built-in or standard JSON parsers.
  3. Language independent: Most modern programming languages support JSON.
  4. Compact: JSON is often less verbose than equivalent XML.

JSON compared with XML

JSON representation:

{"name": "Ali", "age": 30}

The same data in XML:

<person>
  <name>Ali</name>
  <age>30</age>
</person>

For this simple example, JSON uses fewer characters. XML still has capabilities that can make it a better fit for document-centric workflows and some integration requirements.

Common uses of JSON

  • Web APIs: Many services use JSON for request and response bodies.
  • Configuration: Files such as package.json define project metadata and scripts in Node.js projects.
  • Browser storage: Applications often serialize structured data before storing it in local storage.
  • System integration: JSON provides a widely supported format for exchanging data between services.
  • Databases: Some NoSQL databases support JSON-like documents; MongoDB stores BSON, a binary representation with a JSON-like data model.

JSON tools on our website

These tools can help with common JSON tasks:

  • JSON Formatter — format, minify, and validate JSON.
  • Base64 Encoder and Decoder — encode or decode text when a text-safe representation is needed.
  • CSV to JSON Converter — convert tabular data between formats.

Common JSON mistakes

  1. Using single quotes: {'name': 'Ali'} is invalid JSON.
  2. Adding a trailing comma: {"a": 1,} is invalid JSON.
  3. Adding comments: {"a": 1 /* comment */} is invalid JSON.
  4. Failing to escape special characters: Use valid escape sequences such as \\n, \\t, and \\" inside strings.

Summary

JSON is a compact, readable format for exchanging structured data. It is essential when working with APIs, web applications, and many modern software systems. Use our JSON Formatter to format and validate JSON locally in your browser.

Frequently Asked Questions

Is JSON a programming language?

No. JSON stands for JavaScript Object Notation. It is a data-interchange format, not a programming language, although its syntax is derived from a subset of JavaScript object notation.

What is the difference between JSON and XML?

JSON is generally more compact and convenient for common web APIs. XML provides additional document-oriented features and may be preferable for some complex document and enterprise integration use cases.

Is JSON secure?

JSON is a text format; security depends on how an application handles it. Parse input as data, validate its structure, and never execute untrusted JSON as code.

How can I validate JSON?

Use a JSON validator or parse it with JSON.parse in JavaScript and handle parsing errors. Our tool reports syntax errors with useful line and column information.
