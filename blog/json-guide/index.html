راهنمای فرمت‌بندی و رفع خطاهای JSON

📅 ۲۲ آبان ۱۴۰۵ ⏱️ ۴ دقیقه مطالعه

امروزه JSON (JavaScript Object Notation) زبان مشترک تبادل داده در وب است. از APIهای ابری گرفته تا فایل‌های تنظیمات یک برنامه ساده، همه از JSON استفاده می‌کنند. اما کار با JSON خام می‌تواند دشوار و مستعد خطا باشد.

چرا فرمت‌بندی (Pretty-Print) اهمیت دارد؟

وقتی یک داده JSON را از یک API دریافت می‌کنید، معمولاً به صورت یک خط طولانی و فشرده (Minified) است. خواندن این داده‌ها برای انسان تقریباً غیرممکن است. فرمت‌بندی یا مرتب‌سازی JSON (معمولاً با تودرتویی ۲ یا ۴ فاصله) ساختار داده را شفاف می‌کند و پیدا کردن کلیدهای خاص را بسیار آسان‌تر می‌سازد.

می‌توانید از ابزار فرمت‌بندی JSON ما برای این کار استفاده کنید. این ابزار کاملاً در مرورگر شما اجرا می‌شود و هیچ داده‌ای را به سرور ارسال نمی‌کند.

اگر با مفاهیم پایه JSON آشنایی ندارید، ابتدا مقاله JSON چیست؟ را بخوانید.

خطاهای رایج در JSON

JSON بسیار سخت‌گیر است. یک کاما اضافه یا یک کوتیشن جاافتاده می‌تواند کل فایل را نامعتبر کند:

  • کامای انتهایی (Trailing Comma): در JSON، برخلاف JavaScript، وجود کاما بعد از آخرین آیتم یک آبجکت یا آرایه مجاز نیست.
  • استفاده از تک‌کوتیشن: تمام کلیدها و رشته‌ها باید درون کوتیشن دوگانه ("") قرار گیرند.
  • کامنت‌گذاری: JSON از کامنت‌ها (// یا /* */) پشتیبانی نمی‌کند.

اهمیت اعتبارسنجی (Validation) و امنیت

قبل از ارسال داده‌ها به یک API یا ذخیره آن‌ها در دیتابیس، باید مطمئن شوید که JSON شما از نظر ساختاری (Syntax) کاملاً معتبر است. استفاده از ابزار اعتبارسنجی JSON می‌تواند به سرعت خطاها و شماره خط آن‌ها را به شما نشان دهد.

هشدار امنیتی: هرگز داده‌های حساس (مانند کلیدهای API، رمزهای عبور یا اطلاعات شخصی مشتریان) را در وب‌سایت‌های ناشناس فرمت نکنید. همیشه از ابزارهایی استفاده کنید که پردازش را به صورت محلی (Client-Side) انجام می‌دهند.

جمع‌بندی

کار با JSON بخش جدایی‌ناپذیر توسعه وب است. با رعایت قوانین ساده، استفاده از ابزارهای محلی امن و فرمت‌بندی صحیح، می‌توانید از بروز باگ‌های آزاردهنده جلوگیری کنید.

JSON (JavaScript Object Notation) is widely used to exchange data between web applications and services. Raw JSON is often minified into one long line, which can be difficult to inspect. Formatting makes the structure easier to read, while validation checks whether the text follows JSON syntax.

Why pretty-print JSON?

Pretty-printing adds indentation and line breaks to reveal nested objects and arrays. It makes keys and values easier to locate and helps developers compare API responses or configuration files. Minification does the opposite: it removes unnecessary whitespace to make the serialized text smaller.

Common JSON syntax errors

  • Trailing commas: A comma after the last item in an object or array is not valid JSON.
  • Single quotes: JSON strings and object keys must use double quotation marks.
  • Unquoted keys: Object property names must be strings in double quotes.
  • Comments: Standard JSON does not allow // or block comments.
  • Missing delimiters: Every opening brace, bracket, and quotation mark must have a matching close.

Validate before using the data

Before sending JSON to an API or storing it, parse it and validate its structure against the application's expected schema. Syntax validity alone does not prove that the values are correct or safe for your application.

Handle untrusted JSON as data

Use a standard JSON parser and validate the fields you expect. Do not evaluate or execute untrusted JSON as JavaScript. Escape data appropriately when displaying it in HTML, and avoid placing secrets in public configuration files or examples.

Privacy reminder: Avoid pasting API keys, passwords, customer records, or other confidential values into unknown websites. Prefer a trusted local-processing tool and review its network behaviour when the data is sensitive.

Summary

Formatting improves readability; validation checks syntax; schema validation checks whether the data meets application requirements. Use our JSON Formatter for local formatting and validation, and read our introduction to JSON for the underlying data format.

Frequently Asked Questions

Why should JSON be formatted?

Pretty-printing adds indentation and line breaks so nested objects and arrays are easier to inspect. Minification removes unnecessary whitespace to reduce the size of the serialized text.

What are common JSON syntax errors?

Common errors include trailing commas, single-quoted strings, unquoted object keys, comments, and missing quotation marks or brackets.

Can JSON contain comments?

No. Standard JSON does not support comments. Some configuration formats extend JSON, but those files are not strict JSON.

Is it safe to paste sensitive JSON into an online formatter?

Only if you understand the site's processing and privacy practices. Prefer tools that process input locally and avoid pasting secrets into services you do not trust.
